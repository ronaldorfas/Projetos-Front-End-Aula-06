## 1. ❓ Por que gerenciar um projeto Front-End?
Projetos Front-End tendem a crescer de forma rápida e orgânica. Quando não há um planejamento estruturado, a equipe costuma enfrentar problemas como:
* ❌ Tarefas esquecidas;
* ❓ Requisitos confusos ou mal interpretados;
* 🔄 Retrabalho constante;
* 🔀 Conflitos complexos no Git;
* ⏰ Atrasos na entrega;
* 🔌 Problemas de integração entre componentes e APIs;
* 📉 Dificuldade para acompanhar o progresso real do projeto.

Por outro lado, ao aplicar processos de gestão eficientes, o projeto ganha:
* 👤 Responsabilidades claras;
* 🎯 Prioridades bem definidas;
* 📦 Entregas incrementais e contínuas;
* 📊 Acompanhamento transparente do progresso;
* ✨ Redução drástica de retrabalho.

---

## 2. 🗂️ Gestão de Projetos Front-End
Gerenciar projetos Front-End consiste em organizar **pessoas, tarefas, tecnologias e prazos** para transformar uma ideia inicial em uma aplicação funcional. Durante todo o ciclo de vida, as decisões precisam ser planejadas, acompanhadas de perto e ajustadas para garantir entregas contínuas e alinhadas aos objetivos.

---

## 3. 📝 Gestão de Requisitos
O fluxo de desenvolvimento normalmente se inicia com uma ideia, que passa por etapas estruturadas:
1. **Transformação:** A ideia é convertida em requisitos claros.
2. **Organização:** Os requisitos são estruturados em um backlog.
3. **Execução:** As atividades passam por ciclos de priorização, desenvolvimento, revisão, testes e disponibilização aos usuários.

---

## 4. 🔗 Requisito, História e Tarefa
Para estruturar o trabalho, é fundamental entender a diferença de granularidade:
* 📌 **REQUISITO:** O sistema deve permitir o gerenciamento de tarefas.
* 👤 **USER STORY:** Como usuário, quero criar uma tarefa.
* ✅ **TAREFAS:** 
  * Criar formulário
  * Criar componente
  * Validar campos
  * Integrar API
  * Criar testes

---

## 5. 📥 Gestão do Backlog
O backlog reúne funcionalidades, melhorias, correções de bugs e outras atividades necessárias para desenvolver e evoluir o produto. Os itens recebem prioridades diferentes, permitindo que a equipe concentre esforços inicialmente nas demandas mais importantes.

---

## 6. ⚖️ Gestão de Prioridade e Estimativa
* **Priorização:** Ajuda a equipe a determinar a ordem em que as funcionalidades devem ser desenvolvidas, considerando objetivos, necessidades e restrições.
* **Estimativas:** Auxiliam a equipe a compreender a complexidade relativa das atividades antes de assumir determinado conjunto de tarefas.

---

## 7. ✔️ Definition of Done (Critérios de Conclusão)
A *Definition of Done* estabelece os critérios obrigatórios para considerar uma tarefa realmente concluída dentro do projeto. Exemplos:
* Código implementado;
* Testes realizados;
* Revisão (code review) concluída;
* Responsividade verificada;
* Integração realizada.

---

## 8. 🔄 Scrum no Desenvolvimento Front-End
O Scrum é um framework ágil utilizado para desenvolver produtos complexos de forma incremental, permitindo inspeção frequente, adaptação rápida e entregas contínuas. No Front-End, ele auxilia a organizar requisitos, priorizar funcionalidades, planejar Sprints e acompanhar o trabalho da equipe.
